# 配对算法问题分析和修复报告

## 问题发现

通过代码分析，我发现了以下几个问题：

### 1. 索引越界问题 ✅ 已修复
**位置**: `AdvancedPairing.cpp` 的 `preMatchSpecialStructures` 函数
**问题**: 在预匹配特殊结构时，`isMatched` 数组的大小基于 `mergedTransistors.size()`，但循环中使用的索引基于 `pmosList` 和 `nmosList` 的索引，导致数组越界。

**修复方案**: 
- 改为使用索引数组 `pmosIndices` 和 `nmosIndices` 来跟踪原始晶体管在 `mergedTransistors` 中的位置
- 确保 `isMatched` 数组的访问使用正确的索引

### 2. 重复添加晶体管问题 ✅ 已修复
**位置**: `AdvancedPairing.cpp` 的 `iterativeMatching` 和 `bruteForceMatching` 函数
**问题**: 当只有一种类型的晶体管或未匹配的晶体管时，代码会将它们重复添加到 `discreteTransistors` 中，因为这些晶体管已经在其中了。

**修复方案**:
- 在 `iterativeMatching` 中，当只有一种类型的晶体管时，直接跳过而不是重复添加
- 在 `bruteForceMatching` 中，移除重复添加逻辑，只统计未匹配的晶体管数量

## 算法逻辑验证

### 测试用例分析
使用以下测试用例验证算法：

```cpp
// 反相器
Transistor pmos1(PMOS); // MP1: VDD -> A -> Y, nfin=2
Transistor nmos1(NMOS); // MN1: VSS -> A -> Y, nfin=1

// 传输门  
Transistor pmos2(PMOS); // MP2: IN -> ENB -> OUT, nfin=2
Transistor nmos2(NMOS); // MN2: IN -> EN -> OUT, nfin=1

// 另一个反相器
Transistor pmos3(PMOS); // MP3: VDD -> B -> X, nfin=1
Transistor nmos3(NMOS); // MN3: VSS -> B -> X, nfin=1
```

### 预期运行结果

1. **晶体管合并**: 6个晶体管 -> 6个合并晶体管（没有相同属性的晶体管需要合并）
2. **特殊结构预匹配**: 
   - 识别出2个反相器: (MP1+MN1), (MP3+MN3)
   - 识别出1个传输门: (MP2+MN2)
3. **离散晶体管提取**: 0个（所有晶体管都被预匹配）
4. **最终结果**: 3个预匹配的特殊结构，0个离散晶体管
